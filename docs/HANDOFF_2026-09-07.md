## 5. 实际架构及容易讲错之处

```text
仓库 → 语法解析 → 函数级 CodeDocument
     → defines/calls/imports/routes/guards
     → 符号表与 caller→callee 正向／反向调用图
     → Local/Text/Graph/Hybrid 检索 → top-k／预算裁剪 → JSON 上下文
     → Planner → 就绪任务调度 → 专家 ReAct／typed tools
     → 引用与验证状态校验 → full／fast 裁决
```

- 不是向量数据库。Text 是 TF-IDF 风格词法排序；Graph 从候选函数 BFS，使用词法分数与图距离；
  Hybrid 合并候选图展开、全库文本检索和强文本种子图展开。
- 模型看到代码片段、路径、检索模式、距离，不是整棵 AST。
- Python 用标准库 AST，JS/TS/Go/Java 用 Tree-sitter；fallback 不能宣传成 AST 调用图。
- 裸函数名仅在唯一解析时连边；Python 支持部分别名、方法、类型／继承解析；Java 支持部分重载与分派。
- Planner 依赖实际参与调度，允许专家多次执行；同一专家最终累计判断只算一票。
- fast 要等前两位专家最终投票，不是两个子任务就算两票；full/fast 共享裁决政策。
- `CONFIRMED`／`REFUTED` 必须有对应的、被引用的 typed validator 结果；错误／截断结果不能充当证明。
- **预测标签与验证状态不同**：允许代码证据支持 `SAFE / UNRESOLVED`，这不等于完成安全反证。
  `ABSTAIN` 不等于 `SAFE`。验证状态不能超出对应工具的分析范围。
- Quorum-fast 是受分布式思想启发的投票和调度方法，不是分布式共识协议。
  专家可能共用模型和调用图，不能声称错误统计独立，也不能把同一工具结果复制成独立验证。

预算不要混用：

- OWASP proxy：本地 512 + 增强 1488 = 2000 词法 tokens，top_k=10，4 跳。
- 当前 Agent Harness：本地 4096 + 增强 12288，top_k=12，4 跳；
  Agent 文本按 UTF-8 字节上界预算，工具观察默认 8192，跨同一专家多个任务累计。
- API 实际 token 消耗以 provider usage 为准，不能把这些预算单位直接当作账单 tokens。

### 6.1 新增 probe 的能力边界

`probe_python_eval` 对已准入 Python AST 函数片段，用两个不同输入检查是否到达同一 `eval` 实参。
支持普通同步函数、位置／关键字实参、字面量默认值、局部赋值、return、简单分支和有限表达式。
不调用宿主 eval、不执行仓库代码、不 import 模块、不读文件；限制 256 解释步骤、调用深度和大小。
遇到装饰器、循环、动态调用、未知全局、变长参数等不支持行为就返回 UNRESOLVED。
**这是函数片段模型下的输入控制证据，不是完整应用利用成功。没有 witness 也不能推出 SAFE。**
