# Behavior-preserving project restructure

**Current layout:** the follow-up cleanup at the end of this record removes all
71 compatibility modules. The package root now contains only `__init__.py` and
`cli.py`; earlier compatibility decisions below describe the intermediate stage.

This is an engineering restructure, not a model experiment or an improvement claim.
No provider calls are part of its validation. Existing artifacts and frozen experiment
configurations remain historical inputs; new source locations necessarily produce a
new source fingerprint and cannot reuse an earlier live admission.

## Baseline

- Original checkout: `fe6e879` (`feat: modularize core subsystems and add heldout experiment benchmarks`).
- Original complete offline suite: **649 passed in 24.31s**.
- Added frozen scripted E1–E5 / deterministic outputs and seven public JSON schemas:
  **10 characterization checks passed**, followed by **659 passed in 24.62s**.
- The original source/config/test/docs files were copied outside the repository before
  implementation. A manifest recorded sizes and modification times for all 15,492
  existing artifact files so accidental artifact edits can be detected at completion.

## Scope

Preserve detector labels, tool behavior, evidence checks, model prompts, retrieval and
observation budgets, planner dependencies, one final ballot per expert, experiment
stop conditions, source identities, and existing JSON/launch contracts. New tests
exercise these behaviors rather than replacing them with import-only checks.

Module moves change Python implementation locations and require tests that patch
module globals to patch the canonical owner. Compatibility imports must export the
same function/class objects, not copies or subclasses. Historical run JSON remains
readable without changing it.

## Known semantic issues deliberately outside this restructure

The independent review found issues that need separately reviewed behavior changes:

1. The permission analyzer can stop after a nonconstant branch and miss a later chmod,
   while its bounded-mode policy can still return typed refutation.
2. The dataflow analyzer treats a literal fixed-program argv as non-shell, including
   direct `bash -c` arguments, unlike the equivalent variable assignment.
3. Conflicting citation roles produce an unhelpful generic correction message.
4. A command constructor chosen as the dataflow sink gives NOT_ESTABLISHED because
   it contains no execution sink; diagnostics should distinguish that case.
5. Legacy advisory acceptance combines expected predictions with run validity.

Preserving current behavior in a structural migration does not endorse these semantics.
The original regression expectations and raw evidence remain available for subsequent
focused repairs. No unresolved finding is reclassified just to make a refactor pass.

## Follow-up: retire the compatibility layer

The user requested a clean package tree, explicitly retiring old Python module
paths. All 71 forwarding modules were removed: 50 root files, the old `experts/`
and `validation_tools/` packages, and `runtime/execution.py`. Implementation and
ordinary tests import canonical owners directly. The small documented root object
API remains; there are no old-path aliases or replacement forwarding modules.

| Batch | Changes | Validation |
| --- | --- | --- |
| Baseline | Preserve current uncommitted work in an external backup | 726 passed in 28.84s |
| 1 | Migrate remaining test imports and explicit schema lookup | 46 targeted; 727 full passes in 29.89s |
| 2 | Delete 71 modules, update ownership/CLI tests and current documentation | 39 targeted; 727 full passes in 25.97s |
| 3 | Reduce 47 launchers and remove obsolete advisory entrypoint exports | 54 targeted; 729 full passes in 25.76s |

The removal/layout tests failed before deletion. The first complete removal check
found one remaining dynamically constructed `runtime.execution` import in a test
subprocess; it was migrated to `evaluation.execution` with the configuration-read
guard unchanged, then the full suite passed. Old/new-path identity assertions were
replaced by canonical ownership and public-root API checks; the four retired-facade
export cases became one public-root export check. These are intentional contract
changes, not removed detector assertions. Parser, prompt, tool-schema, evidence,
output-schema and scripted behavior goldens remain unchanged.

The 47 launchers now contain only the imports needed by their original main guards:
**1,612 lines reduced to 331**. Every main guard's AST and its arguments matched
the pre-cleanup version. The two standalone subject workers remain byte-identical.
The advisory gate/matrix entry modules also lost obsolete infrastructure reexports
and an unused duplicate pointer writer; lifecycle pointer behavior is still tested.

Supported module commands are now:

```bash
uv run --no-sync python -m cv_agent.runtime.admission
uv run --no-sync python -m cv_agent.evaluation.quorum_probe
```

The old Python module paths are intentionally no longer supported. Existing
`cv-agent` commands, shell commands, frozen configs and result JSON remain intact.
The wheel was rebuilt offline, contains neither retired modules nor obsolete root
files, and imports all **165** remaining modules. Its four offline CLI commands
passed with checkout source/scripts removed from import paths. All frozen configs
and both standalone probes match the pre-cleanup backup. All **15,492** historical
artifact files match their recorded paths, sizes and modification times.
No credentials were loaded, no paid model was called, and no history was reset.
