每轮问题先写失败测试，再修改实现、跑完整离线测试、重跑真实矩阵，失败记录没有删除。
主要修复包括：

1. **权限控制流漏扫与过强否定：** 遍历可支持的正常分支汇合和 Try 后续语句；混合终止、
   绑定改写、异常类型求值副作用，以及尚未建立异常可达性的 handler 内权限操作保持 UNRESOLVED。
   额外负控发现 handler 内 chmod 曾被错误当成可达，已在第五轮前修复。
2. **shell argv 语义不一致：** 保留显式 shell、绝对 shell 路径、executable 覆盖的可能流；
   为不重赋值、不修改、不逃逸的局部普通 argv 保留结构信息。
3. **证据角色冲突与纠正耗尽：** 拒绝同一观察或其别名占据多个显式角色，给出引用/字段反馈；
   独立证据错误一起反馈，使固定步数中的纠正能同时解决多个问题，不扩预算。
4. **权限门槛引用绕过：** 按候选已观察证据执行门槛，不因模型省略静态检查、隐藏引用或重分类
   观察而放行；支持权限实质判断的验证结果必须完整、被引用且绑定同候选与源码。
5. **局部鉴权证据不足：** get_guards 补充直接 lookup→delete 的输入参数、资源变量、主体参数名
   提示、所有权比较原文。重赋值、错误资源/会话和 return 后死代码不能生成该关联。
   这些仍是静态局部事实，不把未知调用方授权、数据库策略或参数名当成已验证身份。
6. **预测与验证状态混淆：** 澄清候选级 SANITIZED 可支持 SAFE/UNRESOLVED，静态风险证据可支持
   未确认的漏洞预测；模型不得仅因缺少动态 exploit 就自动弃权，也不得将预测提升为 CONFIRMED。

本次总测试从 741 增至 819，新增 78 个案例。完整过程见 [闭环记录](EXPERIMENT_LOOP_2026-09-22.md)。

## 研究结论边界

所有样本已反复参与开发，`claim_eligible=false` 保持不变。六个快照上的一次验收通过不能
支撑跨项目泛化、生产安全证明或随机运行稳定性。后续研究需冻结实现和协议，用新的独立样本
及预先确定的重复运行计划评估覆盖率、严格召回、误报、成本和波动；本报告不将开发结果包装为
held-out 研究结论。
