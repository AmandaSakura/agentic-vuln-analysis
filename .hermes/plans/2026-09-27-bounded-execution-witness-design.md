# B 方案：有界执行见证设计（待确认范围）

**目标。** 建一个与样本无关的离线见证器：在固定源码快照上执行真实入口，到首个命令边界时记录调用，再在另一隔离进程测量 shell 如何解释受控探针。hp003 是开发诊断，`claim_eligible=false`；现有 `hp003_callsite.py` 仅作人工核对记录，不注册为通用证明能力，也不计入原六格成绩。

## 要证明的性质

声明的 hp003 场景是 Linux/POSIX、`env_manager=LOCAL`、`enable_mlserver=True`、本地**已存在**且文件名含 shell 元字符的模型目录。两个快照使用同一个 `model_uri` 字节串、良性对照、入口参数、运行器和隔离策略；尽量使用同一组固定依赖，若版本必须不同，则记录差异且不作单变量归因。记 `P(x,e)` 为：这次真实 `serve` 调用把 `model_uri` 控制的字符传到命令边界，并由 POSIX Bash 当作语法解释。

| 输出 | 所需证据 | 可以声称的范围 |
| --- | --- | --- |
| 危险见证 | 真实入口到达命令边界，捕获的 argv 含唯一探针；受限 Bash 重放发生展开，良性对照正常 | `P(x,e)` 成立；若候选性质是“在声明前提下**存在**危险路径”，可作为该开发候选的一条完整正证据 |
| 字面量见证 | 同一入口和探针到达边界；重放保留字面量，且此前没有已覆盖的相关命令事件 | **只否定本次输入与环境下的该条观测路径**；不能推出整类输入或整个 `serve` 安全 |
| 调用点 SAFE | 字面量见证，另有基于真实源码、真实 `bash -c` 消费上下文的通用静态证明：该调用点对任意 builtin 字符串都保持转义，且引用后未被改写 | 仅限声明的 Popen 调用点；`hp003_callsite.py` 的手写 wrapper 不单独满足“通用静态证明” |
| 原候选 SAFE | 上述调用点证明，**再加**下载链、其他 helper、副作用和所有相关路径在声明输入类内均已覆盖 | 若缺任一部分，原 `command-execution` 整函数候选仍为 `UNRESOLVED`，不能把一次负观察升级为 SAFE |

## 执行与隔离

见证器读取**数据化调用清单**（仓库提交/文件摘要、模块与类、构造参数、方法、入口参数、环境、探针路径），不执行样本专用 wrapper，不按 case ID 或期望标签分支。子进程在导入目标源码前核对 checkout 与依赖版本、安装并用自定义事件验证 `sys.addaudithook`；导入后核对实际 `__file__` 来源。记录 `subprocess.Popen`、`os.system`、`os.exec`、`os.posix_spawn`、`os.spawn`、`os.fork`、`os.forkpty` 等事件的顺序、各事件可用参数，并冻结 worker 的 cwd 与环境。钩子在**首个**命令事件写出记录后抛异常，宿主立即终止子进程；若先遇到其他执行事件、钩子未生效、异常被吞掉或没有到达预期边界，则记缺口，绝不报 SAFE。钩子不能替换 `Popen` 的返回值，所以首事件之后的路径不声称已运行。

复用现有受管理的 fixture 子进程、资源限制、结果管道、Landlock 与 seccomp，并补足命令执行系统调用的阻断；审计钩子只负责观测，**不是沙箱**。Bash 测量在第二个最小权限进程中完成，只接受已识别的 shell argv 形状，并原样重放捕获的命令文本；在最小 `PATH` 中仅提供同名的惰性参数记录程序，其他形状返回 `UNRESOLVED`。两阶段都禁网络、限制时间/内存/输出，目标源码进程不实际启动捕获的命令。[Python 审计事件表](https://docs.python.org/3.13/library/audit_events.html)列出事件名；[官方钩子文档](https://docs.python.org/3.13/library/sys.html#sys.addaudithook)明确钩子可阻断操作但不构成沙箱。

每次产物保存源码/运行器/依赖摘要、输入与良性对照、导入来源、沙箱策略、事件序列、原始 argv、Bash 版本与重放结果，以及未覆盖项。原生/`ctypes` 绕过、其他输入类别、其他 `env_manager`、其他平台、钩子中止之后的执行路径均不在这份见证的否定结论内。

## 离线验收与停点

先用自建合成 fixture 做四组正反控：直接拼接、`shlex.quote`、helper 先执行命令、引用后改 argv。测试必须证明首事件截断、遗漏事件和沙箱失效都导致 `UNRESOLVED`。随后在隔离环境安装两份固定快照的依赖，使用同一清单和探针分别运行，记录每个缺口；这是开发诊断，不进入 pytest、也不请求模型。只有两版的**已声明性质**都闭合、且原候选与局部调用点的结果没有混算，才另行决定是否运行 hp003 的一个模型臂；三臂对比仍暂停。

**待拍板的范围。** 建议第一版把 `REFUTED` 限定为一次调用的局部观测，原整函数 SAFE 保持未定。若目标是直接证明原候选 SAFE，需要先补一项覆盖整类输入及 helper 副作用的独立证明义务；审计钩子加一次负例不够。
