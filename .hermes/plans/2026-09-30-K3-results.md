# K3 environment preparation: paired development control

K3 produced two fresh, source-bound Python 3.12.12 witness environments for the development MLflow pair. Both contexts load successfully with the same four inherited, identity-bound read grants. No new grant was accepted. This is environment and offline scripted-contract evidence; it is not autonomous scenario discovery or a held-out claim.

The first cache-only attempt retained the supplied hash locks but could not install the a/b `aiokafka` wheels from the then-local uv cache. Its separate unavailable reports are under `artifacts/witness_environment_rebuild/four_leaf/prepared_{a,b}`. A preregistered second attempt used the same hash-locked requirements and wheel identities with the fixed PyPI index (`https://pypi.org/simple`); a made 140 recorded index requests (21 fresh GET, 119 revalidations, all to `pypi.org`), and b reused the warmed cache with no actual request. The actual request URLs are in `artifacts/witness_environment_rebuild/cached_ready/network-request-ledger.json`; the original PyPI preparation reports and logs remain under `artifacts/witness_environment_rebuild/pypi_hash_locked`. No target distribution source was installed into site-packages: only its wheel metadata was installed, while imports resolved to the clean checkout.

After the cache was populated, a *new* cache-only, `allow_network=false` preparation for each snapshot completed with zero network URLs. The source-bound target import and current witness-kernel bootstrap succeeded under the original four read grants. Both restricted import traces still show seven unaccepted read denials, including the directory `/sys/devices/system/cpu` which is ineligible for a leaf grant. The denials remain in each context report and its proposal list; none is effective. K3 readiness means import and bootstrap succeeded under that unchanged policy. It does not attest future branch execution, which the witness checks separately. Structural trace errors or target/kernel import failures still block context loading.
